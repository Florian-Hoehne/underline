# Requirements

Derived from `docs/vision.md`. Terms are defined in `docs/glossary.md`.

## Functional Requirements

| ID     | Title                          | User Story                                                                                                                                                                                       | Priority | Status   |
|--------|--------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------|----------|
| FR-001 | Create workspace               | As a user, I want to create a workspace in a directory of my choice and be asked for its default format, with Markdown preselected, so that new notes are stored in the format the project uses. | High     | Open     |
| FR-002 | Open workspace                 | As a user, I want to open an existing directory as a workspace so that I can work on notes that already exist, for example in a git repository.                                                 | High     | Open     |
| FR-003 | Create note                    | As a user, I want to create a note that is stored in the default format of the workspace so that I do not have to choose a format for every note.                                             | High     | Open     |
| FR-004 | Format from file extension     | As a user, I want every note to keep the note format given by its file extension (`.md` or `.adoc`) so that a workspace can hold Markdown and AsciiDoc notes side by side.                      | High     | Open     |
| FR-005 | Rename note                    | As a user, I want to rename a note and have the local links to it updated so that links in other notes keep working.                                                                            | High     | Open     |
| FR-006 | Delete note                    | As a user, I want to delete a note after confirming it so that the workspace holds only notes I still need.                                                                                       | High     | Open     |
| FR-007 | Search notes                   | As a user, I want to search the text of all notes of the workspace so that I find a note without knowing its name.                                                                             | Medium   | Open     |
| FR-008 | Edit source                    | As a user, I want to edit the Markdown or AsciiDoc markup of a note directly in the source view so that I keep full control over the stored text.                                              | High     | Open     |
| FR-009 | Edit in facade                 | As a user, I want to edit a note in the facade, which looks and works the same for every note format, so that I can write without knowing the markup.                                          | High     | Open     |
| FR-010 | Switch editing view            | As a user, I want to switch a tab between the source view and the facade at any time so that I can use the view that suits the edit at hand.                                                    | High     | Open     |
| FR-011 | Format indicator               | As a user, I want the facade to show a format indicator with the note format the note is stored in so that I know which options and markup apply.                                              | High     | Open     |
| FR-012 | Format-specific options        | As a user, I want the facade to offer the options that only the note's format supports, such as image captions in AsciiDoc, so that I can use the full power of the format.                    | High     | Open     |
| FR-013 | Additional note formats        | As a user, I want further Markdown flavors and markup formats to become available as note formats so that I can use Underline with notes written for other tools.                              | Low      | Deferred |
| FR-014 | Export to other note format    | As a user, I want to export a note from Markdown to AsciiDoc or from AsciiDoc to Markdown so that I can hand it to a tool that reads only the other format.                                     | High     | Open     |
| FR-015 | Export to HTML                 | As a user, I want to export a note to a standalone HTML file with its diagrams and images so that people without Underline can read it in a browser.                                           | High     | Open     |
| FR-016 | Export to PDF                  | As a user, I want to export a note to a PDF file with its diagrams and images so that I can print or send it.                                                                                   | High     | Open     |
| FR-017 | Note overview                  | As a user, I want the note overview on the left to list the notes of the workspace with the recently opened ones first so that I reach the notes I work on quickly.                            | High     | Open     |
| FR-018 | Open notes in tabs             | As a user, I want every note I open to appear in its own tab so that I can keep several notes open and switch between them.                                                                    | High     | Open     |
| FR-019 | Note properties                | As a user, I want the tool panel on the right to show the properties of the active note (file path, note format, size, last change) so that I see where and how it is stored.                  | High     | Open     |
| FR-020 | Status bar location            | As a user, I want the status bar to show the directory of the workspace and the state of the last git sync so that I know where my notes are kept.                                             | High     | Open     |
| FR-021 | Status bar messages            | As a user, I want the status bar to report each saved note and each error so that I notice when something was stored or went wrong.                                                            | High     | Open     |
| FR-022 | Choose theme                   | As a user, I want to choose a theme from Light, Dark, GitHub Light, GitHub Dark, Solarized Light, Solarized Dark, Night Owl, Ubuntu, Nord, Dracula, and Gruvbox so that the app suits my taste and lighting. | High     | Open     |
| FR-023 | Formatting toolbar             | As a user, I want a toolbar that formats the selected text (heading, bold, italic, code, list, quote, link, image, table) in both editing views so that I can format without typing markup.    | High     | Open     |
| FR-024 | Vim input mode                 | As a user, I want to edit in the Vim input mode so that I can use the Vim keys I am used to.                                                                                                     | High     | Open     |
| FR-025 | Nano input mode                | As a user, I want to edit in the Nano input mode so that I can use the Nano keys I am used to.                                                                                                   | High     | Open     |
| FR-026 | Input mode commands            | As a user, I want the status bar to show the active input mode and its most important commands so that I do not have to remember them.                                                          | High     | Open     |
| FR-027 | Fold sections                  | As a user, I want to fold and expand sections of a note in the source view and in the facade so that I can focus on the part I am working on.                                                  | High     | Open     |
| FR-028 | Toggle line numbers            | As a user, I want to show or hide line numbers so that I see them only when I need them.                                                                                                        | High     | Open     |
| FR-029 | Line number side               | As a user, I want to place the line numbers on the left or on the right of the editor so that they fit my reading habit.                                                                        | Medium   | Open     |
| FR-030 | Minimap                        | As a user, I want a minimap of the active note in the editor so that I see where I am in a long note and jump by clicking into it.                                                             | High     | Open     |
| FR-031 | Copy on select                 | As a user, I want text, an image, or another element that I select to be copied to the clipboard automatically so that I can paste it without an extra command.                                | High     | Open     |
| FR-032 | Switch off copy on select      | As a user, I want to switch copy on select off so that selecting does not overwrite my clipboard when I do not want it to.                                                                     | High     | Open     |
| FR-033 | Drop images and files          | As a user, I want to drag an image or another file into a note so that it is copied into the workspace and inserted as an image or a link at the drop position.                                | High     | Open     |
| FR-034 | Drop links                     | As a user, I want to drag a link, for example from a browser, into a note so that it is inserted as a link at the drop position.                                                                | High     | Open     |
| FR-035 | Highlight code blocks          | As a user, I want code blocks to be syntax-highlighted for their language so that code in notes is easy to read.                                                                                | High     | Open     |
| FR-036 | Render PlantUML                | As a user, I want PlantUML diagrams in a note to be shown as diagrams so that I see the picture, not only its source.                                                                           | High     | Open     |
| FR-037 | Render Mermaid                 | As a user, I want Mermaid diagrams in a note to be shown as diagrams so that I see the picture, not only its source.                                                                            | High     | Open     |
| FR-038 | Diagrams follow theme          | As a user, I want rendered diagrams and highlighted code to use the colors of the active theme so that they match the rest of the app.                                                         | High     | Open     |
| FR-039 | Enlarge diagrams and images    | As a user, I want to enlarge a diagram or an image so that I can read its details.                                                                                                               | High     | Open     |
| FR-040 | Follow local link              | As a user, I want a click on a local link to open the linked note in a new tab, or to offer to create it when it does not exist, so that I can move through my notes like a wiki.            | High     | Open     |
| FR-041 | Outline                        | As a user, I want an outline of the headings of the active note in the tool panel and to jump to a heading by clicking it so that I reach a section quickly.                                   | High     | Open     |
| FR-042 | Code index                     | As a user, I want a list of the code blocks of the active note in the tool panel and to jump to one by clicking it so that I find code quickly.                                                 | High     | Open     |
| FR-043 | Figure index                   | As a user, I want a list of the images and diagrams of the active note in the tool panel and to jump to one by clicking it so that I find figures quickly.                                     | High     | Open     |
| FR-044 | Autosave                       | As a user, I want every change to a note to be saved to the local disk automatically so that I never lose an edit and never have to save by hand.                                             | High     | Open     |
| FR-045 | Git sync                       | As a user, I want a workspace that is a git repository with a remote to be pulled and pushed at a configurable interval (default every 5 minutes) so that my notes are backed up and current on all my machines. | High     | Open     |
| FR-046 | Sync conflicts                 | As a user, I want to be shown a note that was changed both locally and on the remote, with both versions kept, so that a sync never overwrites a change silently.                              | High     | Open     |
| FR-047 | Show branch                    | As a user, I want to see the current git branch of the workspace so that I know which line of work I am editing.                                                                                | High     | Open     |
| FR-048 | Show changed notes             | As a user, I want to see which notes have changes that are not committed yet so that I know what a commit would contain.                                                                        | High     | Open     |
| FR-049 | Show diff                      | As a user, I want the tool panel to show the diff of the active note against the last commit so that I can review my changes.                                                                  | High     | Open     |
| FR-050 | Create and switch branch       | As a user, I want to create a git branch and switch between branches so that I can work on a line of notes without touching the others.                                                       | High     | Open     |
| FR-051 | Commit                         | As a user, I want to commit the changed notes with a message so that the history records what I changed and why.                                                                               | High     | Open     |
| FR-052 | Push                           | As a user, I want to push the commits to the remote on demand so that I can publish them before the next git sync.                                                                             | High     | Open     |
| FR-053 | Pull                           | As a user, I want to pull from the remote on demand so that I get changes made elsewhere before the next git sync.                                                                             | High     | Open     |
| FR-054 | Agent lists notes              | As an agent, I want to list the notes of the workspace through the MCP server so that I know which notes exist.                                                                                 | High     | Open     |
| FR-055 | Agent reads note               | As an agent, I want to read the content of a note through the MCP server so that I can use it in my work.                                                                                       | High     | Open     |
| FR-056 | Agent writes note              | As an agent, I want to create a note or change part of a note through the MCP server, in its note format, so that the user and I work on the same notes.                                      | High     | Open     |
| FR-057 | Agent cursor                   | As a user, I want to see the agent cursor next to my user cursor in an open note while an agent is connected so that I see where the agent is reading or writing.                               | High     | Open     |
| FR-058 | Hide agent cursor when offline | As a user, I want the agent cursor to be hidden while the MCP server is switched off or no agent is connected so that it never shows a position nobody is editing.                            | High     | Open     |
| FR-059 | Switch MCP server              | As a user, I want to set agent access to off, read only, or read and write so that an agent reaches my notes only as far as I allow it.                                                      | High     | Open     |
| FR-060 | MCP install                    | As a user, I want MCP install to register the MCP server in Claude Code, Claude Desktop, Cursor, VS Code (Copilot), Codex, or Gemini CLI so that my agent can use the workspace without manual setup. | High     | Open     |
| FR-061 | MCP configuration snippet      | As a user, I want to copy a ready configuration snippet for the MCP server so that I can connect any other MCP client by hand.                                                                  | High     | Open     |
| FR-062 | Create todo                    | As a user, I want to create a todo with a title so that I can track the work I am heading towards.                                                                                               | High     | Open     |
| FR-063 | Todo due date                  | As a user, I want to give a todo a due date so that I know by when it has to be done.                                                                                                            | High     | Open     |
| FR-064 | Todo urgency                   | As a user, I want to give a todo an urgency so that I can tell the pressing todos from the others.                                                                                              | High     | Open     |
| FR-065 | Todo scheduled date            | As a user, I want to give a todo a scheduled date so that I know on which day I plan to work on it.                                                                                            | High     | Open     |
| FR-066 | Link todo to notes             | As a user, I want to link a todo to one or more notes and open them from the todo so that the work and its material stay together.                                                             | High     | Open     |
| FR-067 | Todo list                      | As a user, I want to list the todos sorted by due date or urgency and filtered by open or done so that I see what to do next.                                                                 | High     | Open     |
| FR-068 | Complete todo                  | As a user, I want to mark a todo as done so that the list shows only the work that remains.                                                                                                     | High     | Open     |
| FR-069 | User settings                  | As a user, I want my default settings to be kept in the user settings file so that every workspace starts with them.                                                                           | High     | Open     |
| FR-070 | Workspace settings             | As a user, I want the workspace settings file to override single user settings for one workspace so that a project can use, for example, AsciiDoc or another theme.                            | High     | Open     |
| FR-071 | Remember settings immediately  | As a user, I want every setting I change in the interface (theme, input mode, panel sizes, line numbers, copy on select, open tabs) to be stored right away so that it is kept after a restart or a crash. | High     | Open     |
| FR-072 | Create workspace as git repository | As a user, I want to create a new workspace as a git repository, optionally linked to a git remote, so that my notes are versioned and can be synced from the start. | High     | Open     |

## Non-Functional Requirements

| ID      | Title                    | Requirement                                                                                                                                                         | Category        | Priority | Status |
|---------|--------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------|----------|--------|
| NFR-001 | Startup time             | The app shows the last opened note within 1 second of start for a workspace of 1,000 notes on a machine with an SSD.                                               | Performance     | High     | Open   |
| NFR-002 | Typing latency           | A typed character appears within 16 milliseconds in notes of up to 10,000 lines, in both editing views.                                                            | Performance     | High     | Open   |
| NFR-003 | Large workspaces         | The note overview of a workspace of 10,000 notes appears within 1 second, and search over it answers within 1 second for 95% of queries.                          | Scalability     | Medium   | Open   |
| NFR-004 | Diagram rendering        | A diagram of up to 200 elements is rendered within 2 seconds, and typing stays within the latency of NFR-002 while it renders.                                     | Performance     | High     | Open   |
| NFR-005 | Autosave delay           | A change is written to the local disk at most 2 seconds after the last keystroke, so a crash loses at most 2 seconds of typing.                                     | Availability    | High     | Open   |
| NFR-006 | No half-saved notes      | A note is never left half saved: after a crash or power loss during a save, the note holds either its previous or its new content.                                | Availability    | High     | Open   |
| NFR-007 | Format fidelity          | Opening a note and leaving it without an edit leaves it unchanged; an edit in the facade changes only the edited paragraph, list, table, or other block.          | Portability     | High     | Open   |
| NFR-008 | Agent changes visible    | A change the agent writes through the MCP server appears in the open tab of that note within 1 second.                                                             | Performance     | High     | Open   |
| NFR-009 | Settings stored          | A setting changed in the interface is written to its settings file within 1 second.                                                                                 | Availability    | High     | Open   |
| NFR-010 | Theme contrast           | Every theme reaches a contrast ratio of at least 4.5:1 for body text and 3:1 for interface controls (WCAG 2.1 AA).                                                  | Usability       | High     | Open   |
| NFR-011 | Keyboard access          | Every function of the menus, toolbar, tool panel, and git controls can be reached by keyboard alone.                                                                | Usability       | High     | Open   |
| NFR-012 | New note formats         | A further note format (FR-013) becomes available in the facade, the tools, the export, and to the agent at once, with no change to how the user works with notes. | Maintainability | High     | Open   |
| NFR-013 | Same features everywhere | Every functional requirement works the same on Linux, Windows, and macOS.                                                                                          | Portability     | High     | Open   |
| NFR-014 | Offline use              | Every function except git push, git pull, and git sync works without a network connection, including diagram rendering and export.                                | Availability    | High     | Open   |
| NFR-015 | Notes stay local         | No note content leaves the machine except through git push to the workspace's remote and through the MCP server to a connected agent.                             | Security        | High     | Open   |
| NFR-016 | Agents on this machine   | Only an agent the user runs on the same machine can reach the MCP server; it cannot be reached from another machine.                                              | Security        | High     | Open   |

## Constraints

| ID    | Title             | Constraint                                                                                                                                   | Category    | Priority | Status |
|-------|-------------------|----------------------------------------------------------------------------------------------------------------------------------------------|-------------|----------|--------|
| C-001 | Platforms         | Underline runs as a desktop app on Linux, Windows 10 or later, and macOS 13 or later.                                                        | Operational | High     | Open   |
| C-002 | Plain files       | Notes are stored as plain text files with the extension `.md` for Markdown and `.adoc` for AsciiDoc, which other editors can open and change. | Business    | High     | Open   |
| C-003 | Markdown display  | A Markdown note looks the same in Underline as in the GitHub and GitLab web interfaces, including tables, checklists, and strikethrough.     | Business    | High     | Open   |
| C-004 | AsciiDoc display  | An AsciiDoc note looks the same in Underline as in the GitHub and GitLab web interfaces.                                                     | Business    | High     | Open   |
| C-005 | Diagram languages | Diagrams are written in PlantUML or Mermaid inside the note, as other tools that render these languages expect them.                          | Business    | High     | Open   |
| C-006 | Settings files    | Settings are kept in files named `underline.yaml`: the user settings file in the user's home directory, the workspace settings file in the root directory of the workspace. | Business    | High     | Open   |
| C-007 | Git credentials   | Underline uses the access to git remotes that the user has already set up for git on the machine and keeps no passwords of its own.          | Business    | High     | Open   |
| C-008 | License           | Underline is open source under the MIT license.                                                                                              | Business    | High     | Open   |
